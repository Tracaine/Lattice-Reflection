# Decision register: selected draft baseline

ART-013. All decisions below are **proposed**, not user-approved implementation. They are the recommendations used consistently throughout revision 1. The user authorized drafting and reasonable defaults; this record does not invent approval or runtime evidence. Changes must identify affected IDs and update contracts/tests before implementation.

| ID | Choice and forces | Viable alternative considered | Consequences / reversal cost / validation |
| --- | --- | --- | --- |
| DEC-001 | Three.js WebGL2 + VRM 1.0 with three-vrm; user import and portable rig semantics | Unity: stronger animation tooling/native rendering, but larger engine-specific content/bridge surface. TalkingHead: faster prebuilt speech/avatar features, but a different rig/shape contract. | Moderate renderer replacement cost behind INT-005/011. Validate import, expressions, retargeting and frame rate before accepting ASM-001/002. |
| DEC-002 | Electron + TypeScript/React and one broker utility process; consistent Windows rendering/audio and one-language core | Tauri/native host: smaller footprint but Rust/native bridge and OS-WebView differences. Browser + local server: portable UI but an added listener/auth/deployment boundary. | Electron footprint and native module packaging are costs. Host replacement is moderate behind INT-010; Android still requires a separate host. |
| DEC-003 | SQLite single writer, explicit repositories, FTS5, copied immutable assets, OS-protected secrets | JSON files: easier start but weak transactional history/receipts. Hosted database: adds account/network dependency. | Low-to-moderate later storage adapter cost, high data migration cost if semantics drift. Prove crash, migration, backup, export before M1. |
| DEC-004 | Separate provider inference, session backend, companion protocol, and renderer ports | Expose OpenAI/Pipecat frames throughout the app: fewer early translations but provider/host coupling and ambiguous authority. | More small contracts initially; cheap provider additions, protected renderer/memory. Verify prohibited imports and equivalent traces across adapters. |
| DEC-005 | Deterministic mock backend/speech/clock first; keep real integration tests separate | Begin with a live paid endpoint: faster live impression but credentials/network nondeterminism obscure playback bugs. | Fixtures must not be mistaken for real synthesis. No cost or network prerequisite for M0. |
| DEC-006 | Rule director + explicit resource arbitration; optional model suggestions and portable clips | Unrestricted model-selected raw animation or proprietary neural generation: richer motion potential but poor reproducibility and missing private assets. | Baseline can look simple; plugin seam permits better motion later. User-visible visual review is a gate, not inferred from tests. |
| DEC-007 | Local reviewed memory and sourced diary, separate from transcript; external context owner negotiated | Automatic vector-memory ingestion/reflection: more automation but weak inspectability, extra cost and cross-channel ambiguity. | Ordinary retrieval may need expansion after measurements. Preserve provenance/scope so embeddings can be added without changing truth rules. |
| DEC-008 | Sample-timed speech, epoch-fenced cancellation, single audible avatar, durable command acceptance | Packet-time animation or separate unsynchronized speech/body players: simpler prototypes but drift and interruption races. | More protocol/clock tests up front. Keep sample semantics if replacing audio engine. |
| DEC-009 | Windows window first; shared contracts/browser modules, Android host later | Simultaneous native Windows/Android launch: broader reach but doubles lifecycle/audio/storage uncertainty before a working vertical slice. | Mobile feasibility remains open; no promise of portable Electron packaging or automatic cross-device sync. |
| DEC-010 | Atomic scoped role bindings, capability profiles, per-turn snapshots; no automatic cross-connection fallback | SDK-wide “OpenAI compatible” abstraction with inferred defaults/fallbacks: less config, but parameter/model/cost surprises. | Explicit connection/profile UI required. Owner changes routes deliberately; compatibility tests precede new adapters. |

Speech ownership is part of DEC-004/008: TTS/STT is independent of text inference. Provider-side routing inside a chosen gateway (such as OpenRouter) must be described separately from client fallback.

Dependency versions are resolved and pinned in WRK-001 using compatibility constraints from primary manifests, with a recorded version matrix and lockfile. Selecting patch versions is ordinary implementation work; changing these architectural choices requires recording a revision. Exact versions are not falsely reported as installed in this design-only workspace.
